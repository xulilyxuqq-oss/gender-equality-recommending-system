# 基线推荐模型实现说明

## 1. 模块拆分

| 模块 | 输入 | 算法流程 | 输出 |
| --- | --- | --- | --- |
| `config.py` | `k`、`candidate_size`、`top_n`、隐式反馈分数、是否检查先修课 | 校验配置范围 | `BaselineConfig` |
| `models.py` | 无外部输入 | 定义课程、近邻、评分、推荐结果和稀疏索引  | 统一的数据对象 |
| `data_loader.py` | 用户、课程、交互 JSONL；目标用户 ID | 校验用户和课程；读取可选 `completed_course_ids`；三次顺序扫描交互数据；只加载目标用户及潜在邻居 | `LoadedData` |
| `similarity.py` | 稀疏交互索引、目标用户、`k` | 通过课程—用户倒排索引查找共享课程用户；计算 Jaccard；选前 `k` 个 | `Neighbor` 序列 |
| `candidates.py` | 目标用户、近邻、课程目录 | 合并邻居课程；移除已学课程；检查先修条件 | 候选课程 ID 序列 |
| `scoring.py` | 候选课程、近邻相似度、邻居评分 | 计算相似度加权评分，跳过分母为零的课程 | `ScoredCourse` 序列 |
| `baseline.py` | 课程目录、交互索引、模型配置 | 串联近邻、候选、评分和排序；生成 Top-M 并截取 Top-N | `Recommendation` 序列 |
| `output.py` | 推荐结果、可选输出路径 | 序列化为 UTF-8 JSONL | 文件或标准输出 |
| `cli.py` | 命令行参数 | 加载数据、运行模型、写出结果 | 进程退出码与 JSONL 结果 |

## 2. 关键口径

- 用户相似度使用课程集合的 Jaccard 系数。
- `comment > 0` 时使用原始分数；`comment == 0` 时使用可配置的隐式反馈分数，默认值为 `1.0`。
- 预测分为邻居相似度加权平均：`Σ(J × score) / Σ(J)`。
- 候选课程必须是近邻交互过、目标用户尚未交互的课程。
- 默认要求目标用户已经完成候选课程的全部先修课程。用户表存在 `completed_course_ids` 时使用该字段；字段缺失时回退到交互历史，保持旧数据兼容。
- `completed_course_ids` 仅用于资格判断，不参与 Jaccard 相似度或预测分计算。
- 推荐结果按预测分降序排列；并列时按 `course_id` 升序排列，保证结果可复现。
- `candidate_size` 控制模型保留的 Top-M 候选，`top_n` 控制最终展示的 Baseline Top-N，且前者不得小于后者。

## 3. 大数据处理策略

当前交互数据量较大，因此不执行全量用户两两比较。加载器针对指定目标用户对交互文件进行三次顺序扫描：

1. 获取目标用户的课程历史。
2. 找出至少共享一门课程的潜在邻居。
3. 仅加载目标用户和潜在邻居的完整交互记录，并构建倒排索引。

这种方式保持 Jaccard 计算结果不变，同时显著降低目标用户数量较少时的内存占用。

## 4. 运行方式

```bash
python -m workflows.baseline_model.run `
  --user-id U_53 `
  --k 20 `
  --candidate-size 50 `
  --top-n 10 `
  --output output/recommendations.jsonl `
  --candidates-output output/candidates.jsonl
```

可以重复传入 `--user-id`，一次为多位用户生成推荐结果。
