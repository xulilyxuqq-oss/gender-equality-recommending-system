# 性别公平课程推荐系统用户端产品与接口规格（MVP）

## 1. 文档目的

本文档定义用户端 MVP 的页面功能、智能体流程、前后端接口、数据持久化规则和验收标准，供前端、FastAPI 后端和推荐模型联调使用。

用户画像只包含三类信息：

- 姓名 display_name；
- 性别 gender_code；
- 经用户确认的已学课程 completed_course_ids。

用户不需要接触课程 ID。用户通过自然语言描述学过的课程，智能体从课程库中检索相似课程并逐项请求确认；只有用户明确确认的课程才能写入画像。

## 2. MVP 范围

### 2.1 本期包含

- 用户注册、登录、令牌刷新和退出；
- 智能体流式对话；
- 姓名、性别和已学课程采集；
- 自然语言课程描述、相似课程检索和逐项确认；
- 用户画像确认与修改；
- 协同过滤推荐和无历史用户的热门课程兜底；
- 基于群体公平策略快照的在线重排；
- 推荐结果、课程详情、推荐历史和收藏；
- 加载态、空状态、错误态和权限校验。

### 2.2 本期不包含

- 学习计划；
- 课程评价正文；
- 课程简介、详细大纲和教学资源；
- 管理后台和研究指标面板；
- 多性别组公平算法；
- 用户主动填写兴趣、难度偏好或课程评分。

## 3. 约束与术语

### 3.1 性别字段

当前数据集和公平算法只支持两个性别组：

| 值 | 含义 |
| --- | --- |
| 1 | 男 |
| 2 | 女 |

这是当前模型能力的限制，不代表完整的性别分类。前端应在采集位置提供简短说明，且不得根据姓名或对话内容推断性别。

### 3.2 课程术语

- **已学课程**：用户确认自己已经学习过的课程。
- **先修课程**：候选课程要求用户预先完成的课程。
- **隐式交互**：已学课程在推荐模型中同步形成 comment=0 的交互；模型按配置的隐式反馈分数处理。
- **课程解析**：把用户自然语言中的课程描述映射到课程库候选的过程。
- **未决解析**：已经生成候选、但用户尚未确认或拒绝的课程解析。

## 4. 用户主流程

~~~text
首页
  → 注册或登录
  → 进入智能推荐
  → 智能体读取已有画像
  → 补充姓名
  → 补充性别
  → 用户自然语言描述已学课程
  → 智能体检索相似课程
  → 用户逐项确认、拒绝或重新描述
  → 画像确认
  → 保存画像
  → 生成推荐
  → 推荐结果
  → 课程详情 / 收藏 / 推荐历史
~~~

如果用户明确表示没有学过任何课程，可跳过课程解析并确认空的已学课程列表。后端随后使用热门课程兜底策略。

## 5. 页面功能规格

### 5.1 首页

#### 页面目标

说明系统用途，并引导用户开始推荐或查看历史结果。

#### 展示内容

- 系统名称和一句话介绍；
- 推荐流程说明：填写画像、确认课程、获得推荐；
- “开始推荐”主按钮；
- 已登录用户显示“查看推荐历史”和“我的收藏”；
- 未登录用户显示“注册”和“登录”。

#### 页面状态

- 未登录：点击受保护入口后跳转登录页，并保留原目标地址；
- 已登录且画像已确认：允许直接开始新一轮推荐；
- 已登录但画像未完成：进入智能推荐页继续补充。

### 5.2 注册与登录

#### 注册字段

- 用户名；
- 密码；
- 确认密码。

注册只创建账号和登录凭据，不采集、推断或写入姓名和性别。用户首次进入智能推荐页后，由智能体在对话过程中依次询问姓名、性别和已学课程，并在用户最终确认后写入正式画像。

#### 登录字段

- 用户名；
- 密码。

#### 校验与错误

- 用户名不能为空且不能重复；
- 密码长度为 8–72 个字符；
- 两次密码必须一致；
- 登录失败统一提示“用户名或密码错误”，不暴露用户名是否存在。

### 5.3 智能推荐页

#### 页面布局

- 顶部：页面标题、当前画像完成状态；
- 主区域：用户与智能体消息流；
- 底部：文本输入框、发送按钮、停止生成按钮；
- 消息流内嵌课程确认卡、画像摘要卡和推荐生成状态卡。

#### 课程确认卡

每个候选课程显示：

- 课程名称；
- 所属领域；
- 难度；
- 匹配依据；
- “就是这门课”按钮；
- “都不是”按钮。

用户确认后，卡片进入只读状态并标记“已确认”。用户拒绝全部候选后，智能体应询问用户是否换一种说法或跳过该课程。

#### 交互约束

- 即使检索结果只有一个高置信度候选，也必须由用户确认；
- 前端不得根据用户回复中的“是”“对”等文本自行写入课程；
- 最终确认必须通过课程确认接口完成；
- 同一课程被多次描述时，只保留一条已确认记录；
- 存在未决解析时，不允许最终确认画像。

#### 页面状态

- 流式响应中：禁用重复发送，允许停止生成；
- 大模型不可用：切换到规则式问答流程，不中断画像采集；
- 课程无匹配：显示重新描述和跳过操作；
- 网络断开：保留用户未发送内容，并提供重新连接；
- 会话过期：创建新会话并从持久化画像重新开始。

### 5.4 画像确认页

#### 展示内容

- 姓名；
- 性别；
- 已确认的已学课程列表；
- 尚未解决的课程描述数量。

#### 用户操作

- 修改姓名；
- 修改性别；
- 删除已确认的课程；
- 返回对话继续补充课程；
- 明确舍弃未决解析；
- 确认画像并生成推荐。

#### 确认条件

- 姓名非空；
- 性别为 1 或 2；
- 所有课程解析均已确认、拒绝或明确舍弃；
- 前端提交的 profile_version 与服务端一致。

### 5.5 推荐结果页

#### 展示内容

- 本次推荐生成时间；
- 推荐来源：个性化推荐或热门课程推荐；
- 按排名展示课程卡片；
- 每门课程显示名称、领域、难度、先修课程状态和推荐理由；
- 收藏按钮；
- 查看课程详情入口。

普通用户界面不展示以下内部信息：

- 性别组曝光比例；
- 预测分；
- 公平加分；
- 原始排名；
- 换位成本。

#### 页面状态

- 生成中：展示模型处理步骤，不展示虚假进度百分比；
- 无结果：提示检查已学课程，允许返回修改画像；
- 公平策略不可用：正常显示推荐，不向用户弹出技术错误；
- 历史结果：明确标记生成时间，不自动替换为最新课程数据。

### 5.6 课程详情页

#### 展示内容

- 课程名称；
- 课程领域；
- 难度；
- 是否为高阶课程；
- 高阶课程标记规则；
- 先修课程列表；
- 是否已经满足全部先修课程；
- 收藏状态。

课程简介、课程大纲、评价正文和资源链接在数据源补齐前不显示占位内容。

### 5.7 推荐历史页

#### 展示内容

- 按生成时间倒序排列推荐记录；
- 每条记录显示生成时间、推荐来源和课程数量；
- 支持查看当时的推荐结果快照；
- 支持删除历史记录。

删除采用软删除。删除后默认列表不再返回，但数据库保留审计所需的最小记录。

### 5.8 收藏页

#### 展示内容与操作

- 分页显示收藏课程；
- 显示收藏时间；
- 支持进入课程详情；
- 支持取消收藏；
- 对同一课程重复收藏保持幂等。

## 6. 智能体状态机

| 状态 | 进入条件 | 智能体动作 | 完成条件 |
| --- | --- | --- | --- |
| LOADING_PROFILE | 会话创建 | 读取用户画像 | 画像读取成功 |
| COLLECTING_NAME | 姓名缺失 | 询问姓名 | 用户提供非空姓名 |
| COLLECTING_GENDER | 性别缺失 | 询问性别 | 用户明确选择男或女 |
| COLLECTING_COURSES | 姓名和性别完整 | 请用户描述已学课程 | 用户提供描述或明确没有课程 |
| RESOLVING_COURSES | 收到课程描述 | 拆分描述并查询相似课程 | 每个描述生成解析结果 |
| WAITING_COURSE_CONFIRMATION | 存在候选 | 展示候选并询问 | 用户确认或拒绝 |
| PROFILE_REVIEW | 没有未决解析 | 展示画像摘要 | 用户确认画像 |
| SAVING_PROFILE | 用户确认画像 | 事务性保存画像 | 保存成功 |
| GENERATING_RECOMMENDATIONS | 画像保存成功 | 调用推荐服务 | 推荐成功或失败 |
| COMPLETED | 推荐成功 | 返回推荐入口 | 用户开始新会话 |
| RECOVERABLE_ERROR | 外部服务或网络失败 | 提供重试或降级 | 重试成功或用户退出 |

### 6.1 大模型职责

- 理解用户表达；
- 从一句话中拆分一个或多个课程描述；
- 生成自然、简洁的追问和说明；
- 选择允许的后端工具。

### 6.2 大模型禁止事项

- 不得直接执行 SQL；
- 不得编造课程 ID；
- 不得绕过课程确认接口写入已学课程；
- 不得推断用户性别；
- 不得把其他用户数据写入当前会话；
- 不得在画像最终确认前调用推荐模型。

### 6.3 规则式降级

当大模型不可用时，后端按固定顺序询问姓名、性别和已学课程。课程描述仍调用同一课程解析服务，用户仍需通过课程确认卡完成确认。

## 7. 自然语言课程解析

### 7.1 输入与拆分

输入示例：

~~~text
我学过 Python 入门、线性代数，还有一门机器学习基础课。
~~~

智能体应拆分为：

~~~json
[
  "Python 入门",
  "线性代数",
  "机器学习基础课"
]
~~~

每个短语独立产生 resolution_id，独立确认，避免用户确认其中一门时误写入其他课程。

### 7.2 匹配顺序

1. 标准化课程名称完全匹配；
2. 课程名称模糊匹配；
3. 课程领域关键词匹配。

标准化至少包括 Unicode NFKC、去除首尾空白、合并连续空白、统一英文大小写和忽略常见分隔符。

模糊匹配使用标准化编辑距离或等价的可复现字符串相似度。领域匹配只能作为低优先级候选，不得因为领域相同而自动判定为同一课程。

### 7.3 候选排序

- 每次最多返回 5 个候选；
- 按 match_score 降序；
- 分数相同时按课程名称、课程 ID 升序；
- 同一课程 ID 只出现一次；
- 没有合理候选时返回空数组，不允许大模型补造课程。

匹配原因枚举：

| match_reason | 含义 |
| --- | --- |
| EXACT_NAME | 标准化名称完全一致 |
| FUZZY_NAME | 课程名称相似 |
| FIELD_KEYWORD | 课程领域关键词相符 |

### 7.4 解析状态

| 状态 | 含义 |
| --- | --- |
| PENDING | 等待用户选择 |
| CONFIRMED | 用户确认一个候选 |
| REJECTED | 用户确认所有候选都不是 |
| DISCARDED | 用户明确舍弃该描述 |
| EXPIRED | 解析记录超时失效 |

解析记录默认在创建 30 分钟后过期。过期后必须重新检索，不得继续确认旧候选。

## 8. 推荐策略

### 8.1 个性化推荐

当 completed_course_ids 非空时：

1. 将确认的已学课程同步为隐式交互；
2. 使用课程集合的 Jaccard 系数查找 Top-K 相似用户；
3. 汇总邻居交互过、目标用户未完成的课程；
4. 过滤先修条件不满足的课程；
5. 使用相似度加权评分生成 Top-M；
6. 使用当前公平策略快照进行在线重排；
7. 返回 Top-N。

### 8.2 热门课程兜底

当用户没有确认任何已学课程时：

1. 排除所有存在先修要求的课程；
2. 按交互过该课程的去重用户数降序；
3. 再按大于 0 的评论平均分降序；
4. 最后按课程 ID 升序，保证结果可复现；
5. 对候选应用当前公平策略；
6. 返回 Top-N。

推荐来源标记为 popular_fallback。

### 8.3 公平策略快照

- 应用首次启动且没有可用快照时计算一次；
- 此后每天计算一次；
- 使用固定、男女数量相同的参考用户队列；
- 快照记录策略版本、样本定义、生成时间、男女推荐位置数、高阶课程数、低曝光组、曝光差、fairness_lambda 和 target_gap；
- 在线请求只使用最新有效快照，不为每位用户重新运行整组实验；
- 快照不存在、过期或计算失败时返回原始推荐，并设置 fairness_applied=false；
- 普通用户接口只返回策略版本和是否应用，不返回群体统计详情。

## 9. API 通用约定

### 9.1 基础约定

- 基础路径：/api/v1；
- 请求和响应编码：UTF-8 JSON；
- 时间格式：带时区的 ISO 8601；
- 鉴权：Authorization: Bearer &lt;access_token&gt;；
- 列表接口使用游标分页；
- 不接受前端传入 user_id 代替当前登录用户；
- 所有资源都必须校验所属用户。

### 9.2 分页格式

~~~json
{
  "items": [],
  "next_cursor": "opaque-cursor-or-null",
  "has_more": false
}
~~~

### 9.3 错误格式

~~~json
{
  "error": {
    "code": "PROFILE_VERSION_CONFLICT",
    "message": "用户画像已被更新，请刷新后重试。",
    "details": {
      "expected_version": 4,
      "received_version": 3
    },
    "request_id": "req_01H..."
  }
}
~~~

### 9.4 常用状态码

| 状态码 | 使用场景 |
| --- | --- |
| 200 | 查询、更新或幂等操作成功 |
| 201 | 资源创建成功 |
| 204 | 删除成功且无响应体 |
| 400 | 请求字段或业务参数无效 |
| 401 | 未登录、令牌无效或过期 |
| 403 | 已登录但无权访问资源 |
| 404 | 资源不存在 |
| 409 | 版本冲突、资源状态冲突或解析已完成 |
| 422 | 字段格式校验失败 |
| 429 | 请求频率过高 |
| 503 | 推荐或大模型服务暂时不可用 |

## 10. 认证接口

### 10.1 注册

POST /api/v1/auth/register

~~~json
{
  "username": "lily",
  "password": "example-password"
}
~~~

成功响应：201 Created

~~~json
{
  "account": {
    "account_id": "acct_01H...",
    "username": "lily"
  },
  "access_token": "...",
  "refresh_token": "...",
  "token_type": "Bearer",
  "expires_in": 1800
}
~~~

注册接口不接收姓名或性别，也不创建包含占位值的用户画像。正式用户画像在智能体完成信息采集并获得用户最终确认后创建。

### 10.2 登录

POST /api/v1/auth/login

~~~json
{
  "username": "lily",
  "password": "example-password"
}
~~~

响应包含 account、access_token、refresh_token、token_type 和 expires_in。

### 10.3 刷新令牌

POST /api/v1/auth/refresh

~~~json
{
  "refresh_token": "..."
}
~~~

刷新成功后轮换刷新令牌，旧刷新令牌立即失效。

### 10.4 退出

POST /api/v1/auth/logout

~~~json
{
  "refresh_token": "..."
}
~~~

成功响应：204 No Content。

## 11. 用户画像接口

### 11.1 查询画像

GET /api/v1/me/profile

新注册且尚未完成智能体画像确认的账号返回空画像：

~~~json
{
  "display_name": null,
  "gender_code": null,
  "completed_courses": [],
  "profile_version": 0,
  "status": "DRAFT",
  "confirmed_at": null
}
~~~

已经确认画像的账号返回：

~~~json
{
  "display_name": "小莉",
  "gender_code": 2,
  "completed_courses": [
    {
      "course_id": "C_1001",
      "course_name": "Python 程序设计"
    }
  ],
  "profile_version": 4,
  "status": "CONFIRMED",
  "confirmed_at": "2026-10-01T10:00:00+08:00"
}
~~~

### 11.2 修改姓名或性别

PATCH /api/v1/me/profile

~~~json
{
  "profile_version": 4,
  "display_name": "莉莉",
  "gender_code": 2
}
~~~

只提交需要修改的字段。更新成功后 profile_version 加 1，画像状态变为 DRAFT。

该接口用于修改已经创建的画像。新注册用户的姓名和性别由智能体写入会话画像草稿，不通过注册接口或此接口提前保存。

### 11.3 查询已学课程

GET /api/v1/me/completed-courses

返回当前持久化的已学课程，不返回会话中的未确认课程。

### 11.4 最终确认画像

POST /api/v1/me/profile/confirm

~~~json
{
  "profile_version": 5,
  "chat_session_id": "chat_01H..."
}
~~~

后端必须：

1. 校验会话属于当前用户；
2. 校验没有 PENDING 的课程解析；
3. 读取会话画像草稿中已确认的课程；
4. 在同一事务中替换完成课程集合并同步隐式交互；
5. 将画像状态更新为 CONFIRMED；
6. 将 profile_version 加 1；
7. 返回持久化后的完整画像。

版本不一致返回 409 PROFILE_VERSION_CONFLICT，存在未决解析返回 409 PENDING_COURSE_RESOLUTIONS。

## 13. 对话接口与 SSE

### 13.1 创建会话

POST /api/v1/chat/sessions

~~~json
{
  "purpose": "RECOMMENDATION"
}
~~~

响应包含 chat_session_id、当前状态、画像草稿和创建时间。已有正式画像时，草稿复制当前画像；新注册用户的草稿以空姓名、空性别和空课程列表初始化，并从 COLLECTING_NAME 状态开始。

### 13.2 查询会话

GET /api/v1/chat/sessions/{chat_session_id}

返回会话状态、历史消息、画像草稿、已确认课程和未决解析。

### 13.3 发送消息并接收流式响应

POST /api/v1/chat/sessions/{chat_session_id}/messages:stream

请求头：

~~~http
Authorization: Bearer <access_token>
Accept: text/event-stream
Content-Type: application/json
~~~

请求体：

~~~json
{
  "message": "我学过 Python 入门和线性代数",
  "client_message_id": "client-msg-001"
}
~~~

前端使用 fetch 读取响应流，不使用无法方便设置 Bearer 请求头的原生 EventSource。

SSE 格式示例：

~~~text
id: evt_001
event: message.delta
data: {"text":"我找到几门可能对应的课程，"}

id: evt_002
event: course.match_required
data: {"resolution_id":"res_01H...","query":"Python 入门","candidates":[]}

id: evt_003
event: done
data: {"chat_session_id":"chat_01H..."}

~~~

事件定义：

| 事件 | 数据用途 |
| --- | --- |
| message.delta | 智能体文本增量 |
| course.match_required | 展示课程确认卡 |
| course.match_confirmed | 更新已确认课程 |
| course.match_rejected | 标记候选被拒绝 |
| profile.updated | 更新画像草稿和版本 |
| profile.ready | 允许进入画像确认 |
| recommendation.started | 展示推荐生成状态 |
| recommendation.completed | 携带推荐记录 ID 和跳转信息 |
| error | 当前流中的可恢复或不可恢复错误 |
| done | 本轮流式响应结束 |

每个事件必须包含单调递增的事件 ID。前端断线重连时携带最后收到的事件 ID，服务端在保留期内补发未确认事件。

### 13.4 确认或拒绝课程候选

POST /api/v1/chat/sessions/{chat_session_id}/course-resolutions/{resolution_id}

确认某一候选：

~~~json
{
  "course_id": "C_1001"
}
~~~

拒绝全部候选：

~~~json
{
  "rejected": true
}
~~~

两个字段必须二选一。后端必须校验：

- 会话属于当前用户；
- 解析记录属于当前用户和当前会话；
- 解析状态为 PENDING；
- 解析记录尚未过期；
- 确认的课程 ID 位于该解析记录的候选集合中。

成功后返回最新画像草稿。重复提交相同确认可返回当前结果；尝试改选其他候选返回 409 RESOLUTION_ALREADY_FINALIZED。

## 16. SQLite 数据设计

后端复用现有 users、courses、course_fields、course_prerequisites、user_completed_courses 和 interactions 表，并增加以下业务表。

### 16.1 新增表

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| accounts | account_id、user_id（可空）、username、password_hash、status、时间字段 | 登录凭据；画像确认前 user_id 为空 |
| refresh_tokens | token_id、account_id、token_hash、expires_at、revoked_at | 刷新令牌轮换与撤销 |
| profile_states | account_id、user_id（可空）、profile_version、status、confirmed_at | 画像版本和确认状态 |
| chat_sessions | session_id、account_id、state、时间字段 | 智能体会话，正式画像创建前也可使用 |
| chat_messages | message_id、session_id、role、content、时间字段 | 对话上下文 |
| chat_draft_completed_courses | session_id、course_id、resolution_id | 会话画像草稿中的课程 |
| course_resolutions | resolution_id、session_id、account_id、query、status、selected_course_id、expires_at | 自然语言解析状态 |
| course_resolution_candidates | resolution_id、course_id、match_score、match_reason、position | 固定候选集合 |
| interaction_provenance | user_id、course_id、source | 区分导入交互和画像生成的隐式交互 |
| recommendation_runs | recommendation_id、user_id、版本字段、来源、生成时间、deleted_at | 推荐历史主表 |
| recommendation_items | recommendation_id、rank、课程快照、理由快照 | 推荐结果快照 |
| favorites | user_id、course_id、created_at | 用户收藏 |
| fairness_policy_snapshots | 策略版本、统计值、参数、生成时间、状态 | 在线公平重排依据 |

### 16.2 画像确认事务

最终确认画像必须在一个数据库事务中：

1. 锁定或重新读取当前画像版本；
2. 校验会话和课程解析状态；
3. 如果账号尚未关联正式用户，分配 user_id 并创建 users 记录；
4. 使用会话草稿更新用户姓名和性别；
5. 替换 user_completed_courses 中的当前用户记录；
6. 为新增已学课程写入 comment=0 的隐式交互；
7. 在 interaction_provenance 标记来源为 PROFILE_COMPLETION；
8. 删除已移除课程对应的 PROFILE_COMPLETION 来源；
9. 仅当课程不存在其他交互来源时删除对应隐式交互；
10. 画像版本加 1 并更新为 CONFIRMED；
11. 提交事务。

任一步失败必须整体回滚。

## 17. 主要错误码

| 错误码 | HTTP | 场景 |
| --- | --- | --- |
| AUTH_INVALID_CREDENTIALS | 401 | 用户名或密码错误 |
| TOKEN_EXPIRED | 401 | 访问令牌过期 |
| PROFILE_VERSION_CONFLICT | 409 | 画像版本不一致 |
| PROFILE_NOT_CONFIRMED | 409 | 未确认画像就请求推荐 |
| PENDING_COURSE_RESOLUTIONS | 409 | 仍有待确认课程 |
| COURSE_NOT_FOUND | 404 | 课程不存在 |
| CHAT_SESSION_NOT_FOUND | 404 | 会话不存在或不可见 |
| RESOLUTION_NOT_FOUND | 404 | 解析不存在或不可见 |
| RESOLUTION_EXPIRED | 409 | 解析已过期 |
| INVALID_RESOLUTION_CANDIDATE | 400 | 确认的课程不在候选集合 |
| RESOLUTION_ALREADY_FINALIZED | 409 | 解析已经确认、拒绝或舍弃 |
| RECOMMENDATION_UNAVAILABLE | 503 | 推荐服务暂时不可用 |
| RATE_LIMITED | 429 | 请求频率过高 |

为避免泄露资源是否属于其他用户，访问他人会话、解析、推荐或收藏时统一返回 404。

## 18. 安全与隐私

- 密码使用 Argon2id 或 bcrypt 保存哈希，禁止明文保存；
- 访问令牌短期有效，刷新令牌保存哈希并支持轮换和撤销；
- 大模型只能调用白名单工具，不能获得数据库连接或任意 SQL 工具；
- 课程 ID 必须来自数据库检索结果；
- 所有写操作校验当前用户、会话、解析记录和资源归属；
- 日志不得记录密码、完整令牌或不必要的对话敏感信息；
- 普通用户接口不返回其他用户数据或男女群体公平统计；
- 性别只用于当前画像和公平策略，不用于公开展示；
- 删除历史记录后，普通查询不再返回对应内容。

## 19. 测试与验收标准

### 19.1 认证与权限

- 注册、登录、刷新和退出均有成功与失败测试；
- 重复用户名被拒绝；
- 过期或撤销令牌无法访问受保护接口；
- 用户不能读取或修改其他用户的会话、解析、推荐和收藏。

### 19.2 画像与课程解析

- 姓名不能为空，性别只能为 1 或 2；
- 正确处理课程名称完全匹配、简称、错别字、多候选和无候选；
- 一句话描述多门课程时，每门课程创建独立解析记录；
- 即使只有一个候选，也必须经过确认接口；
- 拒绝候选不会写入画像；
- 伪造的课程 ID、解析 ID 和跨用户确认被拒绝；
- 重复描述同一课程不会生成重复完成记录；
- 存在未决解析时无法确认画像；
- 过期解析无法确认；
- 画像版本冲突返回 409。

### 19.3 推荐

- 已确认课程同时进入完成课程表和隐式交互；
- 已学课程参与相似用户计算和先修条件判断；
- 有已学课程的用户可获得协同过滤推荐；
- 没有已学课程的用户获得不要求先修课的热门推荐；
- 推荐排序在相同数据和参数下可复现；
- 公平策略存在时返回版本并设置 fairness_applied=true；
- 公平策略缺失或失效时仍返回原始推荐，并设置 fairness_applied=false；
- 普通推荐响应不包含群体曝光数据和内部评分。

### 19.4 对话与 SSE

- SSE 事件顺序与状态机一致；
- course.match_required 包含完整候选确认数据；
- 断线后可从最后事件 ID 恢复；
- 相同 client_message_id 不重复创建用户消息或课程解析；
- 大模型不可用时能够进入规则式降级流程；
- 会话过期后可以从持久化画像创建新会话。

### 19.5 历史与收藏

- 推荐历史保存生成时快照；
- 软删除后默认列表不可见；
- 收藏和取消收藏保持幂等；
- 已删除推荐和收藏操作不会影响课程主数据。

### 19.6 端到端验收

以下流程无需人工修改数据库即可完整运行：

1. 用户注册并登录；
2. 智能体采集姓名和性别；
3. 用户自然语言描述一门或多门已学课程；
4. 系统返回真实课程候选；
5. 用户逐项确认或拒绝；
6. 用户确认画像；
7. 后端事务性保存完成课程和隐式交互；
8. 系统生成并展示推荐；
9. 用户查看课程详情并收藏课程；
10. 用户在历史页重新查看本次推荐快照。

前端和后端实现人员应能仅依据本文档确定页面状态、接口路径、主要字段、写入时机和失败处理，不需要另行决定用户画像范围或课程确认规则。
