# 性别公平课程推荐系统管理端功能与接口规格（MVP）

## 1. 文档目的

本文定义管理端 MVP 的功能边界、页面行为、权限模型、接口契约、数据口径和验收标准，用于前端、FastAPI 后端、推荐模型和公平策略服务共同开发。

本文是目标规格，不代表当前仓库已经实现管理端。现有用户端继续使用 `/api/v1` 下的用户接口；管理端统一使用 `/api/v1/admin`，不得直接复用普通用户令牌访问管理资源。

## 2. 管理端目标

管理端解决以下问题：

- 管理课程、领域、别名和先修关系；
- 查看账号、画像状态和用户侧流程是否正常，不代替用户确认课程；
- 审计自然语言课程匹配质量，并将有效结果沉淀为课程别名；
- 查看推荐运行、热门兜底、失败和公平策略应用情况；
- 计算、检查、启用和回滚公平策略快照；
- 跟踪课程导入任务、后台任务、服务健康和管理员操作记录；
- 在不泄露密码、令牌、API Key 和不必要用户隐私的前提下完成故障排查。

## 3. MVP 范围

### 3.1 本期包含

- 管理员登录、令牌刷新、退出和当前权限查询；
- 仪表盘；
- 课程列表、创建、修改、归档、恢复和详情；
- 课程领域、别名和先修关系管理；
- JSONL 或 CSV 课程批量校验与导入；
- 用户账号列表、画像摘要、会话摘要和账号停用；
- 课程匹配记录审计；
- 推荐运行和结果快照查询；
- 推荐诊断模拟，不覆盖用户历史结果；
- 推荐与公平算法超参数的单组实验、网格扫描、指标对比和结果导出；
- 公平策略快照计算、查看、启用和回滚；
- 后台任务、系统健康和管理员审计日志；
- 加载态、空状态、局部失败、管理身份无效和版本冲突处理。

### 3.2 本期不包含

- 管理员代替用户确认已学课程；
- 管理员直接修改用户姓名、性别或已学课程；
- 物理删除已被画像、交互、推荐或收藏引用的课程；
- 查看用户密码、密码哈希、访问令牌、刷新令牌或智谱 API Key；
- 在管理端直接执行任意 SQL、Python 或系统命令；
- 在线编辑推荐算法代码或大模型系统提示词；
- 财务结算、课程发布审批流、组织层级和多租户；
- 自动根据管理端审计结果改写用户已经确认的历史画像。

## 4. 管理员角色与访问边界

管理端只设置一种角色：`admin`。

所有状态为 `ACTIVE` 的管理员拥有相同的完整管理权限，可以访问全部管理页面和接口，包括课程维护、用户查询、匹配审计、推荐诊断、超参数分析、公平策略、管理员账号和系统状态。

不设置超级管理员、课程管理员、算法管理员、审核员或自定义权限点，也不支持为单个管理员增减模块权限。

后端访问规则：

- 管理令牌必须包含 `actor_type=admin`、`role=admin` 和 `admin_id`；
- 普通用户令牌不能访问任何管理接口；
- 状态为 `DISABLED` 或 `LOCKED` 的管理员不能继续访问；
- 每一次写操作和敏感数据读取仍需记录具体管理员，不能因为权限一致而共用账号；
- 所有管理员都能管理其他管理员账号，但不能停用自己，也不能停用最后一个活动管理员；
- 前端不再根据权限点隐藏菜单，登录成功后展示完整管理导航；
- 唯一角色不降低审计、二次确认、版本冲突和敏感数据保护要求。

## 6. 核心流程

### 6.1 课程修改流程

1. 管理员打开课程详情；
2. 前端读取课程当前 `row_version`；
3. 管理员修改名称、难度、领域、高阶标记或先修课程；
4. 前端本地检查必填项、重复领域和课程自引用；
5. 后端检查课程是否存在、版本是否一致、先修图是否形成环；
6. 更新课程并递增 `row_version`；
7. 生成新的课程目录版本；
8. 写入审计日志；
9. 推荐服务在下次请求中使用新目录，历史推荐快照保持不变。

### 6.2 批量导入流程

1. 上传 JSONL 或 CSV 文件；
2. 服务创建校验任务，不立即修改课程库；
3. 校验字段、重复课程、未知先修课程、先修环和行级冲突；
4. 页面展示新增、更新、跳过和错误数量；
5. 管理员下载或查看错误行；
6. 只有状态为 `VALIDATED` 且无阻塞错误的任务可以提交；
7. 提交后在单一事务中应用数据并生成目录版本；
8. 导入结果和操作人写入审计日志。

### 6.3 匹配审计流程

1. 管理员筛选低分、全部拒绝或无候选的解析记录；
2. 查看原始描述、候选顺序、匹配原因和用户最终选择；
3. 标记为匹配正确、排序欠佳、无有效候选或非课程输入；
4. 可以把规范化描述创建为某门课程的别名；
5. 审计不会修改用户已经确认或拒绝的结果；
6. 新别名只影响之后创建的课程解析记录。

### 6.4 超参数分析流程

1. 管理员选择固定的数据集版本、课程目录版本、评估用户集和随机种子；
2. 选择单组实验或网格扫描；
3. 配置协同过滤参数 `k_neighbors`、`candidate_size`、`top_n`、隐式反馈分数和先修过滤开关；
4. 配置公平参数 `fairness_lambda`、`target_gap` 和 `max_total_cost`；
5. 后端校验参数范围、组合数量和 `candidate_size >= top_n`；
6. 创建异步实验，逐组保存 Recall、NDCG、覆盖率、男女高阶曝光率、曝光差、换位成本和运行耗时；
7. 页面以基线差值、结果表、折线图或热力图展示参数影响；
8. 管理员可以选择实验结果创建公平策略计算草稿，但实验结果不能直接修改线上参数；
9. 所有实验保留完整数据版本、算法版本、参数和随机种子，保证结果可复现。

### 6.5 公平策略发布流程

1. 管理员填写参考队列版本、Top-N、`fairness_lambda`、`target_gap` 和最大换位成本；
2. 后端创建异步计算任务；
3. 任务完成后策略进入 `READY`，页面展示男女样本数、推荐位置数、高阶课程曝光数、曝光率、差值和相关性损失；
4. 管理员确认样本量和质量门槛后启用；
5. 启用操作使原活动策略进入 `SUPERSEDED`，新策略进入 `ACTIVE`；
6. 启用失败时保持原策略不变；
7. 回滚通过重新启用历史 `READY` 或 `SUPERSEDED` 快照完成，不直接编辑快照内容。

## 7. 页面功能规格

### 7.1 管理员登录页

展示用户名、密码和登录按钮，不提供公开注册入口。

行为：

- 登录成功后进入仪表盘并展示完整管理导航；
- 用户端令牌访问管理端时显示“账号无管理权限”；
- 登录失败统一显示“用户名或密码错误”；
- 连续失败触发服务端限流，前端展示剩余等待时间；
- 令牌失效时尝试刷新一次，失败后返回登录页；
- 不在 URL、日志或本地错误信息中出现密码与令牌。

### 7.2 仪表盘

默认统计最近 24 小时，可切换 24 小时、7 天和 30 天。

统计口径：

- 注册账号数：`created_at` 落在时间范围内的普通账号数；
- 已确认画像数：上述注册账号中，在范围结束时间前至少完成一次画像确认的账号数；
- 画像完成率：已确认画像数除以注册账号数，分母为 0 时返回 `null`；
- 课程解析比率：按范围内创建的解析记录最终状态计算；
- 推荐成功率：范围内成功推荐数除以全部结束的推荐运行数，仍在运行的任务不进入分母；
- 热门兜底占比和公平策略应用率：只以成功推荐为分母；
- 推荐耗时：只统计成功的用户请求，不混入诊断模拟。

展示：

- 注册账号数；
- 已确认画像数和画像完成率；
- 新建对话数；
- 课程解析数、候选确认率、全部拒绝率和无候选率；
- 推荐运行数、成功率、热门兜底占比和公平策略应用率；
- 推荐生成 P50、P95 耗时；
- 当前课程目录版本；
- 当前活动公平策略版本与更新时间；
- 失败后台任务和降级服务提醒。

交互：

- 指标点击后进入相应列表并带入筛选条件；
- 时间范围使用绝对时间传给后端；
- 部分统计失败时保留其他模块，并标记具体模块不可用；
- 没有数据时显示 0 和口径说明，不显示虚构趋势。

### 7.3 课程库列表

筛选条件：关键词、领域、难度、高阶标记、状态、是否存在先修课程和更新时间。

表格字段：课程 ID、课程名称、领域、难度、高阶标记、先修数量、状态、目录版本、更新时间和操作人。

操作：

- 查看详情；
- 创建课程；
- 编辑课程；
- 归档课程；
- 恢复课程；
- 管理别名；
- 跳转查看引用该课程的画像、解析和推荐数量，只显示聚合数量。

归档课程不会出现在新的课程检索和推荐候选中，但历史画像和推荐快照仍能显示课程快照。

### 7.4 课程编辑页

字段：

| 字段 | 规则 |
| --- | --- |
| `course_name` | 必填，1 至 200 字符，规范化后不能与活动课程重名 |
| `difficulty_level` | 必填，`standard` 或 `advanced` |
| `fields` | 至少 1 项，每项为受控领域词表中的值 |
| `is_advanced` | 必填布尔值 |
| `advanced_label_rule` | 必填，当前默认 `prerequisite_count>=2` |
| `prerequisite_course_ids` | 可以为空，不能包含自身、重复值、归档课程或形成先修环 |
| `aliases` | 可以为空，规范化后全局唯一 |

当 `difficulty_level`、`is_advanced` 和 `advanced_label_rule` 不一致时，页面必须给出阻塞提示，不能静默修正。

保存前展示变更摘要。发生版本冲突时展示服务器最新值和当前未提交值，由管理员重新选择，不自动覆盖。

### 7.5 课程导入页

展示任务状态、文件名、文件哈希、上传人、创建时间、处理进度、新增数、更新数、跳过数、警告数和错误数。

支持格式：

- JSONL：字段与 `course_info.jsonl` 对齐；
- CSV：多值领域使用 JSON 数组字符串，先修课程使用课程 ID 数组；
- UTF-8，文件大小上限由服务配置返回；
- 不接受压缩包、电子表格宏或任意脚本文件。

错误必须定位到行号、字段、错误码和可理解说明。导入期间离开页面不会取消任务。

### 7.6 用户与画像列表

筛选条件：账号状态、画像状态、性别数据组、是否有已学课程、注册时间和最近活动时间。

默认字段：账号 ID、脱敏用户名、账号状态、画像状态、画像版本、已学课程数量、注册时间和最近活动时间。

管理员拥有敏感字段查看能力，但列表默认只返回脱敏用户名，不直接展示姓名、性别和课程描述原文。管理员进入详情或主动执行敏感筛选时，后端返回所需字段并记录敏感读取审计，避免在大列表中无目的暴露用户数据。

允许操作：

- 查看账号详情；
- 查看画像版本、已确认课程、会话摘要和推荐摘要；
- 因滥用或安全原因停用账号；
- 恢复已停用账号。

不允许操作：

- 代替用户修改画像；
- 代替用户确认候选；
- 查看密码、令牌或完整鉴权日志；
- 批量导出姓名、性别和课程描述原文。

### 7.7 用户详情页

分区展示：

- 账号：状态、注册时间、最近登录、失败登录次数；
- 画像：状态、版本、确认时间、姓名和性别；
- 已学课程：课程名称、确认来源和更新时间；
- 对话：会话状态、开始时间、结束时间、消息数量和未决解析数量；
- 推荐：来源、算法版本、公平策略版本、生成时间和课程数量；
- 收藏：只显示数量，减少与支持场景无关的数据暴露；
- 管理记录：停用、恢复和查看敏感数据的审计记录。

停用账号必须填写原因，提交后二次确认。停用会撤销刷新令牌，并阻止新登录，不删除画像和历史快照。

### 7.8 匹配审计页

筛选条件：解析状态、用户是否确认、最高匹配分区间、候选数量、匹配原因、课程领域、时间范围和审计状态。

列表字段：解析 ID、脱敏账号、原始描述权限遮罩、候选数、最高匹配分、用户选择、解析状态、审计状态和创建时间。

详情展示：

- 原始描述；
- 拆分后的课程短语；
- 每个候选的课程名称、领域、难度、匹配分、匹配原因和排序；
- 用户确认、拒绝或跳过结果；
- 是否重复课程；
- 审计结论和审计人。

创建别名前必须检查别名是否已属于其他课程。冲突时返回已有课程，不允许强制覆盖。

### 7.9 推荐运行页

筛选条件：状态、推荐来源、算法版本、公平策略是否应用、策略版本、课程数量、耗时区间和生成时间。

列表字段：推荐 ID、脱敏用户、来源、状态、算法版本、公平策略版本、结果数量、总耗时和生成时间。

详情展示：

- 输入画像版本和已学课程 ID；
- 原始候选数量和先修过滤数量；
- `collaborative` 或 `popular_fallback` 来源；
- 公平重排是否应用及策略版本；
- 最终课程顺序、课程快照、理由代码和理由文本；
- 失败阶段、错误码和可重试性；
- 不显示其他用户的明细交互，只显示近邻数量和聚合信息。

诊断模拟使用指定画像快照、算法版本和可选公平策略运行，结果标记为 `SIMULATION`，不得写入用户推荐历史或触发通知。

### 7.10 超参数分析页

页面目标是比较推荐质量、公平性和运行成本随超参数变化的趋势，帮助管理员选择后续公平策略计算参数。该页面只运行离线实验，不直接修改线上推荐配置。

#### 实验配置区

固定上下文：

- 数据集版本；
- 课程目录版本；
- 算法版本；
- 评估用户集版本；
- 公平参考队列版本；
- 随机种子；
- 基线实验 ID，可选。

可分析参数：

| 参数 | 含义 | MVP 范围 |
| --- | --- | --- |
| `k_neighbors` | Jaccard 协同过滤近邻数量 | 正整数，建议 1 至 200 |
| `candidate_size` | 公平重排前保留的 Top-M 候选数 | 正整数，必须大于等于 `top_n` |
| `top_n` | 最终推荐课程数量 | 1 至 50 |
| `implicit_score` | `comment=0` 隐式交互用于协同评分时的分值 | 大于 0 且小于等于 5 |
| `enforce_prerequisites` | 是否过滤未满足先修条件的课程 | 布尔值，正式策略必须为 `true` |
| `fairness_lambda` | 公平软正则权重 | 大于等于 0 的有限数值 |
| `target_gap` | 允许的最大男女高阶曝光差 | 0 至 1 |
| `max_total_cost` | 公平换位允许的累计相关性损失 | `null` 或大于等于 0 |

实验模式：

- 单组实验：每个参数只取一个值；
- 网格扫描：每个参数输入离散值数组，执行笛卡尔组合；
- MVP 单次最多 100 个参数组合，超过时前端预警且后端返回阻塞错误；
- 浮点数由后端规范化后参与组合去重；
- 同一实验中的全部组合必须使用相同数据版本、评估用户集和随机种子。

#### 结果指标

每个参数组合展示：

- `Recall@N`；
- `NDCG@N`；
- 课程覆盖率；
- 男组高阶课程曝光率；
- 女组高阶课程曝光率；
- 公平处理前和处理后的曝光差；
- 曝光差改善量；
- 累计换位成本；
- 平均每位用户换位次数；
- 满足目标曝光差的用户或实验比例；
- 无可推荐课程的用户数量；
- 平均运行耗时和峰值内存，可采集时展示。

指标定义：

- `Recall@N` 和 `NDCG@N` 使用同一评估集和留出规则；
- 覆盖率为至少出现一次的课程数除以可推荐活动课程数；
- 曝光率和曝光差沿用公平策略页口径；
- 基线差值等于当前组合指标减去基线组合指标；
- 任一指标分母为 0 时返回 `null`，不能用 0 替代；
- 不同数据集版本或评估用户集版本的实验不能计算直接差值，页面必须标记“不可直接比较”。

#### 结果展示与操作

- 概览：成功组合数、失败组合数、最佳 Recall、最佳 NDCG、最小曝光差和最低换位成本；
- 结果表：支持按任一指标排序、筛选和固定基线行；
- 双轴趋势图：选择一个变化参数和两个指标；
- 热力图：选择两个变化参数和一个指标，其余参数固定；
- 帕累托视图：横轴使用推荐质量，纵轴使用曝光差或换位成本，标出非支配组合；
- 最多选择 5 个组合并排比较；
- 导出 CSV 或 JSON，导出内容包含参数、指标和版本信息，不包含用户级明细；
- 从成功组合创建公平策略计算草稿；
- 克隆实验配置后重新运行；
- 取消仍在排队或支持安全取消的运行中实验。

推荐的默认基线为：`k_neighbors=20`、`candidate_size=50`、`top_n=10`、`implicit_score=1.0`、`fairness_lambda=0`、`enforce_prerequisites=true`。默认值只用于预填，不代表最终线上选择。

### 7.11 公平策略页

策略列表字段：策略 ID、版本、状态、参考队列版本、样本数量、Top-N、男女高阶曝光率、曝光差、低曝光组、相关性损失、生成时间、启用时间和创建人。

指标口径：

- 参考队列中男女用户数必须相同；
- 每组推荐位置数等于该组用户数乘以 Top-N；
- 高阶曝光率等于该组高阶课程推荐位置数除以该组全部推荐位置数；
- 曝光差等于男女高阶曝光率之差的绝对值；
- 样本量不足配置阈值时状态为 `INSUFFICIENT_SAMPLE`，禁止启用；
- 普通用户 API 不返回这些群体统计。

启用策略前展示：当前活动策略、新策略、关键指标差值、相关性损失、最大换位成本和预计影响。策略快照不可编辑，只能重新计算。

### 7.12 后台任务页

展示课程导入、超参数实验、公平策略计算和推荐诊断任务。

通用状态：`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。

允许取消尚未开始的任务。运行中的任务只有实现安全取消点时才允许取消。失败任务可以使用相同参数重新创建，但必须产生新的任务 ID。

### 7.13 审计日志页

筛选条件：管理员、动作、资源类型、资源 ID、结果、时间范围和请求 ID。

展示操作时间、管理员、动作、资源、结果、变更摘要、IP 摘要和请求 ID。敏感值、密码、令牌、API Key 和完整对话内容必须脱敏。

审计日志只读，不提供修改和删除操作。

### 7.14 系统状态页

展示：

- API 服务状态；
- SQLite 或正式数据库连接状态；
- 课程目录加载状态与版本；
- 推荐服务状态与算法版本；
- 当前公平策略是否可用；
- 智谱智能体模式、模型名称和最近成功时间；
- 后台任务队列积压数量；
- 最近 24 小时错误数量。

只展示智谱是否配置和模型名称，绝不返回 API Key、密钥片段或请求头。

## 8. 资源状态定义

## 9. API 通用约定

### 9.1 基础约定

- 基础路径：`/api/v1/admin`；
- 使用 UTF-8 JSON，文件上传接口除外；
- 时间使用带时区的 ISO 8601；
- 鉴权头：`Authorization: Bearer <admin_access_token>`；
- 管理令牌必须包含 `actor_type=admin`、管理员 ID 和固定角色 `role=admin`；
- 普通用户令牌访问管理接口统一返回 403；
- 列表接口使用游标分页；
- 创建导入、超参数实验、计算策略和诊断模拟时支持 `Idempotency-Key`；
- 修改资源必须携带当前 `row_version`；
- 所有写操作和敏感读取记录管理员、请求 ID、资源和结果；
- 不接受前端传入角色或权限列表；所有活动管理员固定拥有完整管理能力。

### 9.2 分页格式

~~~json
{
  "items": [],
  "next_cursor": "opaque-cursor-or-null",
  "has_more": false
}
~~~

游标必须包含已校验的筛选和排序上下文，不能被前端解码后修改。默认每页 20 条，最大 100 条。

### 9.3 排序和筛选

列表接口统一支持：

- `cursor`：不透明游标；
- `limit`：1 至 100；
- `sort`：接口声明的白名单字段；
- `order`：`asc` 或 `desc`；
- `created_from`、`created_to`：绝对时间范围。

关键词搜索参数统一为 `query`。后端必须限制查询长度并对通配符和特殊字符做安全处理。

### 9.4 错误格式

~~~json
{
  "error": {
    "code": "COURSE_VERSION_CONFLICT",
    "message": "课程已经被其他管理员更新，请刷新后重试。",
    "details": {
      "expected_version": 8,
      "received_version": 7
    },
    "request_id": "req_01H..."
  }
}
~~~

### 9.5 常用状态码

| HTTP | 场景 |
| --- | --- |
| 200 | 查询或更新成功 |
| 201 | 资源创建成功 |
| 202 | 异步任务已接受 |
| 204 | 幂等操作成功且无响应体 |
| 400 | 业务参数或文件格式无效 |
| 401 | 管理令牌无效或过期 |
| 403 | 管理员账号不可用或使用普通用户令牌 |
| 404 | 资源不存在或不可见 |
| 409 | 版本、状态、别名或幂等键冲突 |
| 413 | 上传文件超过限制 |
| 422 | 字段格式校验失败 |
| 429 | 登录或接口调用频率过高 |
| 503 | 依赖服务不可用 |

## 23. 数据一致性规则

- 活动课程的规范化名称全局唯一；
- 活动别名的规范化值全局唯一；
- 课程不能把自身作为先修课程；
- 先修关系必须是有向无环图；
- 被历史数据引用的课程只能归档，不能物理删除；
- 课程归档后，其别名不再参与新匹配；课程恢复后别名随课程恢复，除非别名自身已被删除；
- 课程变更不回写历史推荐条目的课程快照；
- 匹配审计不更改用户已经处理的解析结果；
- 超参数实验提交后，数据版本、参数空间和随机种子不可修改；克隆实验必须产生新实验 ID；
- 超参数结果不能直接修改在线推荐配置，只能创建新的公平策略计算任务；
- 同一实验的指标必须来自相同数据版本、评估集版本和计算口径；
- 同一时刻最多一个 `ACTIVE` 公平策略；
- 策略启用失败不能让当前活动策略失效；
- 用户停用和管理员停用必须撤销对应刷新令牌；
- 所有修改使用乐观锁，成功后 `row_version` 加 1；
- 导入提交、别名审计创建和策略启用必须使用数据库事务。

## 24. 安全与隐私

- 管理员密码使用 Argon2id 或 bcrypt 哈希；
- 管理令牌和用户令牌使用不同受众或不同签发配置；
- 管理端默认拒绝访问；只有活动且固定角色为 `admin` 的管理员令牌可以进入，登录后拥有完整管理能力；
- 敏感字段由后端裁剪，不只依赖前端遮罩；
- 查看姓名、性别和课程描述原文属于敏感读取并写入审计；
- 管理接口不得返回密码哈希、JWT 密钥、刷新令牌哈希或智谱 API Key；
- 文件上传校验扩展名、媒体类型、大小和内容，不执行上传内容；
- 登录、导入、超参数实验、策略计算和诊断模拟分别限流；
- 审计日志中的请求体和差异必须脱敏；
- 错误响应不返回堆栈、SQL、磁盘路径或内部凭据；
- 公平指标和超参数实验只在管理端展示，普通用户端继续只返回策略版本和是否应用；
- 当前男女二元分组是数据集和算法限制，页面必须明确标注，不能解释为完整性别分类。

## 26. 前端通用状态

每个页面必须提供：

- 首次加载骨架；
- 筛选刷新中的局部加载；
- 无数据空状态；
- 无搜索结果状态；
- 403 管理身份不可用或使用了普通用户令牌；
- 404 资源不存在；
- 409 版本冲突和恢复入口；
- 网络错误重试；
- 部分模块失败但其他模块仍可使用；
- 长任务离开页面后继续运行，并可从任务中心恢复查看；
- 危险操作二次确认，确认文案写明影响范围；
- 成功操作提供明确反馈，但不使用阻塞式弹窗。

列表筛选条件写入 URL 查询参数，刷新页面和复制链接后可以恢复。敏感原文不得写入 URL。

## 27. 测试计划

### 27.1 认证与管理员角色

- 普通用户令牌不能访问管理接口；
- 所有活动管理员均能访问全部管理模块；
- 接口拒绝创建非 `admin` 角色或自定义权限；
- 管理员停用后旧刷新令牌失效；
- 不能停用自己或最后一个活动管理员；
- 登录失败限流不泄露用户名是否存在。

### 27.2 课程管理

- 创建、修改、归档和恢复课程；
- 课程重名、别名冲突和版本冲突；
- 自引用、未知先修课程和先修环；
- 归档课程不进入新匹配和推荐；
- 历史画像和推荐仍能读取课程快照。

### 27.3 导入

- 合法 JSONL 和 CSV；
- 编码错误、字段缺失、重复 ID、未知领域和未知先修课程；
- 校验期间目录变化；
- 提交事务整体成功或整体回滚；
- 相同幂等键不会重复导入；
- 文件超限和不支持格式被拒绝。

### 27.4 用户与匹配审计

- 用户列表默认裁剪姓名、性别和原始描述；详情或显式敏感查询正常返回并记录审计；
- 敏感读取产生审计日志；
- 停用账号撤销刷新令牌；
- 审计记录不能修改用户最终选择；
- 创建别名只影响之后的解析。

### 27.5 推荐、超参数与公平策略

- 推荐运行列表、详情、失败和热门兜底筛选；
- 诊断模拟不进入用户历史；
- 单组实验和网格扫描正确展开参数组合并去重；
- `candidate_size < top_n`、非法浮点值和组合数超限被拒绝；
- 相同实验可以通过固定数据版本和随机种子复现；
- 不同数据或评估集版本的结果不能直接计算基线差值；
- 失败组合保留参数和错误摘要，不影响成功组合展示；
- 实验结果不能直接修改线上配置；创建策略草稿会重新触发正式策略计算；
- 公平样本不平衡或不足时禁止启用；
- 同一时刻只有一个活动策略；
- 并发启用通过 `expected_active_policy_id` 防止覆盖；
- 新策略启用失败时原策略继续有效；
- 普通用户 API 不泄露群体公平统计。

### 27.6 审计与系统

- 所有管理写操作产生审计记录；
- 审计差异不包含密码、令牌或 API Key；
- 系统状态不返回连接串或密钥；
- 组件部分失败时整体状态为 `DEGRADED`；
- 后台任务失败、重试和取消状态正确。

### 27.7 端到端验收

至少验证以下闭环：

1. 管理员登录并访问完整管理导航；
2. 创建课程并配置先修课程和别名；
3. 用户端能够检索到新课程；
4. 审计一条用户拒绝的课程匹配并创建别名；
5. 后续解析能够使用新别名产生候选；
6. 创建超参数网格扫描并比较 Recall、NDCG、曝光差和换位成本；
7. 从一个成功组合创建公平策略计算草稿；
8. 管理员检查并启用公平策略；
9. 新推荐记录正确保存策略版本；
10. 推荐详情、实验、后台任务和审计日志可以追溯整个过程。

## 28. 实施顺序

### 第一阶段：管理认证与只读观察

- 单一 `admin` 角色的管理员账号和独立令牌；
- 仪表盘、用户摘要、匹配记录、推荐记录和系统健康只读接口；
- 管理操作审计基础设施。

### 第二阶段：课程管理

- 课程、领域、别名和先修关系；
- 乐观锁、归档和目录版本；
- 课程批量校验与导入。

### 第三阶段：算法与公平策略

- 推荐诊断模拟；
- 超参数单组实验、网格扫描、指标可视化和结果导出；
- 公平策略异步计算、质量门槛、启用和回滚；
- 后台任务中心和完整审计链路。

文档完成标准：前端和后端可以仅依据本文实现“管理登录、课程维护、匹配审计、推荐观察、超参数分析、公平策略发布和操作追溯”的完整管理端闭环。
